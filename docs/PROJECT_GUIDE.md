# SR Studio project guide

> Production portfolio and admin workspace for SR Studio. The public site is a TanStack Start/React application deployed as a Cloudflare Worker; its gallery, inquiries, authentication, and existing data layer use Supabase.

## Stack

| Area              | Technology                                                  |
| ----------------- | ----------------------------------------------------------- |
| Website           | React 19, TanStack Start/Router, Vite, Tailwind CSS         |
| Edge hosting      | Cloudflare Workers with Nitro                               |
| Data and identity | Supabase Auth, Postgres, Storage and RLS                    |
| Admin app         | Capacitor Android shell, GitHub Actions signed APK releases |
| UI utilities      | React Query, Zod, Lucide, jsPDF, QRCode                     |

## Local development

```bash
npm install
npm run dev
npm test
npm run build
```

Local credentials belong only in ignored `.env` files. Required client/build values are `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, and (for canonical links) `VITE_SITE_URL`. Never commit service-role keys, Android keystores, passwords, or Cloudflare API tokens.

## Data and security

Run SQL migrations from `drizzle/migrations/` in numeric order before using features that depend on them. The current calendar feature needs `0007_booking_calendar.sql`; public-input hardening is in `0008_harden_public_inputs.sql`.

The public site may insert inquiries and page views only through RLS policies. Admin reads/writes require an authenticated user with the `admin` role. The browser UI redirects guests to sign-in and shows a 403 screen to non-admin users; Supabase RLS is the data-security boundary. Maintain the allowed Auth redirect URLs for `/auth` and `/admin` on every deployed domain.

Report security issues privately through the public vulnerability-disclosure page or by emailing `hello@srstudio.in`. Do not use production data, personal images, credential stuffing, social engineering, denial of service, or high-volume scanning when testing.

## Cloudflare deployment

Production worker: `srcreativ` at `https://srcreativ.srcreativ92.workers.dev`.

```bash
npm run build
npx wrangler deploy
```

`wrangler.jsonc` uses the current Worker compatibility date, `nodejs_compat`, a D1 binding reserved for the Cloudflare migration, and enabled Worker observability/traces. Response headers are applied by `src/server.ts`; do not loosen CSP, clickjacking, or no-store admin/auth protections without review.

Before a domain change, set `VITE_SITE_URL`, configure the domain in Supabase Auth redirects, submit `/sitemap.xml` to Google Search Console and Bing Webmaster Tools, and validate social previews. `robots.txt`, `sitemap.xml`, `security.txt`, metadata, and structured data are generated by the application.

## Site and admin operations

Sign in at `/auth`, then use `/admin`. Settings contains plain-language content, social links, theme/media controls, section order, and per-section visibility switches. Gallery supports preview, selection, deletion, and upload. Calendar marks confirmed bookings in gold and inquiries in blue; booking note bubbles save on blur. VDP & HoF generates and previews recognition PDFs.

For public content, use real business details, real client testimonials/reviews, client-approved photographs, accurate image titles, and descriptive alternative text. Keep NAP (name, address/service area, phone) consistent across the website, Google Business Profile, and social accounts.

## Android release process

Android is a lightweight shell for the live Worker; it does not package the site’s media. Do not produce or commit local APKs. GitHub Actions alone builds the signed release and publishes `SR-Studio-Admin-vX.Y.Z.apk`.

Create one signing key, store it offline, then add these repository secrets:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Release from **Actions → Android APK release → Run workflow** with a semantic version, or push `android-vX.Y.Z`. Android verifies that updates are signed by the same key before installing them. The native updater checks the repository’s latest GitHub Release on app startup.

## Contribution rules

External changes require owner approval. Use focused branches, run `npm test` and `npm run build`, document database/deployment implications, and do not place secrets in commits. Never force-push, rebase, amend, or squash shared history: this repository is connected to Lovable and such rewrites can lose project history.

Treat every contributor with respect. Harassment, discrimination, abuse, and sharing private information are not accepted. Report conduct concerns to `hello@srstudio.in`.
