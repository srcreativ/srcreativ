# Security policy

## Supported version

Security fixes are made on the latest `main` branch and deployed to the current
production Worker.

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability.

Submit a report through the [SR Studio Vulnerability Disclosure Program](/vulnerability-disclosure)
or email [hello@srstudio.in](mailto:hello@srstudio.in) with:

- a clear description of the issue and its impact;
- reproducible steps or a proof of concept;
- the affected URL, account type, or version; and
- a safe way to contact you.

We aim to acknowledge valid reports within five business days and provide a
status update as the issue is assessed. Please avoid actions that could affect
availability, access personal data, or alter production data.

## Safe-harbor expectations

Good-faith research that follows the VDP scope and these rules will be treated
as authorized. Do not use social engineering, denial-of-service testing,
credential stuffing, or automated high-volume scanning.
